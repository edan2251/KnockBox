# Windows 빌드와 시연

Unity에서 직접 빌드하고 다른 Windows PC로 옮기는 안내입니다. 게임 조작은 [플레이 검수](PLAYTEST.md), 접속 설정은 [Photon 설정](../ai_docs/ONLINE_MULTIPLAYER.md#기본-접속과-새-pc-설정), 실제 빌드 결과는 [진행 현황](../ai_docs/progress/PROGRESS.md)을 봅니다.

## 가장 간단한 빌드 순서

1. Unity Hub에서 **KnockBox 프로젝트**를 엽니다. 이 PC의 경로는 `D:/KnockBox`, Unity는 **6000.3.23f1**입니다. 다른 PC에서는 저장소를 받은 경로를 사용합니다.
2. Play를 끄고 수정한 씬·프리팹·설정 에셋을 저장합니다. 맵을 편집했다면 MapAuthoring의 **맵 저장**도 필요합니다. 씬 저장만으로 맵 정의가 저장되지는 않습니다.
3. Console에 빨간 컴파일 오류가 없는지 확인합니다. 오류가 있으면 첫 오류부터 해결하고 빌드합니다.
4. 이전 결과가 필요하면 프로젝트의 `Builds/Windows` 폴더 전체를 날짜가 붙은 별도 폴더로 복사합니다. 다음 빌드는 같은 Windows 폴더를 다시 사용합니다.
5. Unity 상단 **Knockbox → Build → Windows Development**를 누릅니다.
6. 빌드가 끝날 때까지 기다립니다. Console의 **`[Knockbox] 빌드 성공:`** 메시지에 경로·크기·시간·경고 수가 표시됩니다. 폴더에 예전 exe가 있다는 것만으로 성공을 판단하지 않습니다.
7. 프로젝트의 **`Builds/Windows/Knockbox.exe`**를 실행합니다. 이 PC에서는 `D:/KnockBox/Builds/Windows/Knockbox.exe`입니다.

**이 메뉴를 사용하면 Unity를 종료할 필요가 없습니다.** 에디터를 종료해야 하는 경우는 같은 프로젝트를 명령줄 배치 모드로 별도 실행할 때입니다. 두 방식은 동시에 사용하지 않습니다.

## 빌드에 포함되는 내용

현재 [빌드 메뉴](../../Assets/_Project/Editor/BuildMenu.cs)는 Windows 64비트 **개발 빌드**를 만들고 **Main 씬 하나만** 포함합니다. Main에 연결된 UI·보상 맵·모놀리스·경기 맵과 Resources 자료는 Unity의 빌드 과정에서 포함됩니다. Sandbox와 MapAuthoring을 시연 시작 씬으로 넣을 필요가 없습니다.

온라인 예측용 프리팹을 먼저 점검한 뒤 빌드합니다. 현재 파일이 정상이면 Main이나 UI를 새로 만들지 않습니다. 예측 프리팹이 없어서 새로 생성됐다면 생긴 에셋과 `.meta`를 개발자가 확인해야 합니다.

개발 빌드에는 로컬 검수 단축키와 진단 기능이 들어갑니다. **O/P 즉사 키를 일반 대전 중 실수로 누르지 않도록 주의**합니다. 현재 온라인·녹화·재생 중에는 이 치트를 차단합니다. 정식 배포용 비개발 빌드는 별도 검수 대상이며, 이번 시연 절차와 구분합니다.

`Windows Replay Check`는 과거 입력 기록을 검사하는 별도 메뉴입니다. 일반 시연은 `Windows Development`를 선택합니다.

## 다른 PC 전달

**exe 하나가 아니라 Windows 폴더 전체를 전달합니다.** 다음은 함께 필요한 주요 파일·폴더입니다. 빌드 버전에 따라 다른 파일도 생길 수 있으므로 이 목록만 골라 복사하지 않습니다.

- `Knockbox.exe`
- `Knockbox_Data`
- `UnityPlayer.dll`, `UnityCrashHandler64.exe`
- `MonoBleedingEdge`
- `D3D12`, 기타 생성된 런타임 DLL

`*_BurstDebugInformation_DoNotShip` 폴더는 개발용 디버그 정보이므로 시연 전달본에서는 제외할 수 있습니다. 원본 빌드나 백업에서 지울 필요는 없습니다. 로그·검사 결과·이전 녹화도 배포 폴더에 섞지 않습니다.

1. 완성한 폴더를 `KnockBox_Demo_날짜_버전`처럼 복사해 보관합니다. 예: `KnockBox_Demo_20261116_153fb44`.
2. [Paperlogy 고지](../licenses/Paperlogy_OFL.txt) 등 사용하는 외부 자료의 고지를 함께 둡니다. 필요한 출처와 조건은 [에셋 권리 안내](../licenses/ASSET_RIGHTS.md)를 따릅니다. docs 폴더는 Unity 빌드에 자동으로 복사되지 않습니다.
3. 해당 폴더를 ZIP으로 압축해 전달합니다. 받은 PC에서는 **압축을 모두 푼 뒤** exe를 실행합니다. ZIP 안에서 exe만 실행하지 않습니다.
4. 두 PC 시연이면 **같은 ZIP을 양쪽에 전달**합니다. 한쪽만 다시 빌드해 섞지 않습니다.

실행 PC에는 Unity·Unity Hub·Photon SDK 설치가 필요 없습니다. 인터넷 연결은 온라인 대전에 필요하며 로컬 연습은 별개입니다. 이 시연 빌드를 웹이나 스토어에 게시하는 절차는 포함하지 않습니다.

## Photon 온라인 확인

개발 PC의 로컬 Photon 설정에 올바른 App ID가 있어야 온라인이 되는 빌드를 만들 수 있습니다. 빌드에는 접속용 설정이 포함되므로 **빌드를 실행하는 PC마다 App ID를 입력할 필요는 없습니다.** 이 설정과 계정·지역을 시연 직전에 임의로 바꾸지 않습니다.

현재 온라인은 Photon Fusion Host/Client와 기본 3틱 예측 방식입니다. 이전 Unity Relay 빌드와 함께 접속하는 방식이 아닙니다. 모놀리스 호버 전달·선택 대기 설정도 접속 버전에 반영되므로 같은 최신 빌드를 사용합니다.

방 만들기 → 표시된 코드를 상대에게 전달 → 상대가 코드로 참가 → 두 플레이어 준비 → 경기 순으로 확인합니다. Host가 나가면 경기가 종료됩니다. 실제 시연 장소의 네트워크에서 두 PC가 접속되는지는 따로 확인해야 합니다. 로컬 실행 성공이나 빌드 성공만으로 온라인 성공을 판단하지 않습니다.

## 시연 전 직접 검수

1. **메인과 첫 경기:** exe 시작 → 연습 → VS → 3·2·1·GO. 버튼·글꼴·화면 비율을 봅니다.
2. **기본 전투:** 이동·점프·펀치·충전 돌진·잡기/던지기. 무기·총알은 현재 보류입니다.
3. **보상 선택:** 로컬 검수에서 O/P로 한쪽을 두 번 KO시키면 세트 패자의 보상 장면으로 빠르게 갈 수 있습니다. 모놀리스가 솟고, 호버한 선택지가 밝아지며, 클릭 반응·확정 연출·카드 획득·다음 세트가 이어지는지 봅니다. O/P는 온라인 시연에는 쓰지 않습니다.
4. **HUD와 결과:** 선택 중 승점·보유 카드 목록이 보이는지, 최종 결과에서 다시하기와 나가기가 동작하는지 확인합니다.
5. **온라인 시연:** 양쪽이 같은 빌드로 참가하고 조작·카드 선택·재대결을 확인합니다. 이 항목은 실제 두 PC 검수입니다.

현재 카드 능력 효과는 적용되지 않고 선택·획득 흐름만 동작합니다. 발표에서도 능력이 이미 적용된다고 설명하지 않습니다. 최신 모놀리스 클릭 연출의 사용자 검수 여부는 진행 현황에 따로 남깁니다.

## 빌드 실패와 실행 문제

- **메뉴가 안 보임:** 에디터 임포트·컴파일이 끝났는지, Console에 오류가 있는지, 올바른 프로젝트인지 확인합니다.
- **빌드가 실패했는데 exe가 있음:** 이전 빌드일 수 있습니다. 최신 성공 메시지와 파일 갱신 시간을 확인합니다. 실패 원인은 Console의 첫 오류를 개발자에게 전달합니다.
- **빌드 파일을 쓸 수 없음:** 그 폴더에서 실행 중인 Knockbox.exe를 종료하고 다시 빌드합니다. Unity 자체를 종료할 필요는 없습니다.
- **창 제목이나 로그 폴더가 Project_Brawl:** 현재 PlayerSettings의 제품명이 남아 있기 때문입니다. 실행 파일 이름이 Knockbox.exe인 것과 별개이며 시연 직전 이를 바꾸느라 설정을 일괄 수정하지 않습니다.
- **다른 PC에서 실행 불가:** ZIP 전체를 해제했는지, Data·DLL·Mono 폴더가 함께 있는지 확인합니다. 시스템 보안 경고가 나오면 사용자가 직접 내용을 확인합니다.
- **온라인 코드로 참가 불가:** 같은 ZIP인지와 인터넷 연결부터 확인하고 [Photon 설정](../ai_docs/ONLINE_MULTIPLAYER.md#기본-접속과-새-pc-설정)을 봅니다. App ID나 참가 코드를 공개 문서에 적지 않습니다.

기본 실행 로그는 현재 제품 설정 기준 `%USERPROFILE%/AppData/LocalLow/DefaultCompany/Project_Brawl/Player.log`입니다. `-logFile` 인수를 지정한 검사 실행은 지정 경로에 로그를 남깁니다. 로그에는 개인 경로·접속 정보가 포함될 수 있으므로 외부 공유 전 확인합니다.

## File 메뉴의 Build Profiles

이 프로젝트에서는 위의 **Knockbox 전용 메뉴를 우선** 사용합니다. 기본 Build Profiles의 저장 씬 목록에는 Main 외에 Sandbox도 있으므로 전용 메뉴와 포함 씬이 같다고 가정하지 않습니다. 플랫폼·빌드 종류를 바꾸거나 정식 배포용 프로필을 만들 때만 별도 범위로 설정하고 검수합니다.

## 빌드 후 변경 목록

빌드 과정에서 Unity가 `ProjectSettings/ProjectSettings.asset`의 사전 로드 목록에 `Assets/Settings/InputSystem_Actions.inputactions` 참조를 기록할 수 있습니다. 이번 빌드에서도 이 항목과 빈 씬 템플릿 줄의 공백 변경이 생겼습니다. 소스 게임 규칙 변경과 구분해 Fork에서 검토하며, 에이전트가 자동으로 커밋하거나 되돌리지 않습니다. Builds 폴더는 기존 Git 제외 규칙을 유지합니다.
