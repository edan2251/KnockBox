# 게임 흐름 통합 계획

작성: 2026-11-16. 사전 조사 기준: `D:/KnockBox`, main `5af3753`.

**Claude 검토용 기획·작업 계획입니다. 이 문서 자체는 개발 승인이 아니며, 아래 기능은 아직 구현하지 않았습니다.** 사용자와 합의한 방향, 권장안, 미확정 사항을 구분해 정리했습니다. 권장안과 작업 순서는 현행 구조를 확인한 뒤 조정할 수 있습니다.

**현재 전투부터 모놀리스 파워업 선택까지의 분위기가 전체 작업의 기준입니다.**

사용자는 이 구간의 화면 구성과 연출을 좋아합니다. 새로운 스타일로 바꾸려는 작업이 아닙니다. 특히 선택 화면이 일반적인 메뉴가 아니라 게임 맵의 일부처럼 표현되는 점을 유지하고 싶습니다.

사전 조사에서 확인한 특징은 다음과 같습니다.

- 어두운 배경과 선명한 캐릭터 색, 단순하고 묵직한 기하학적 지형.
- 검은 윤곽선, 긴 그림자, 조명으로 강조되는 캐릭터와 오브젝트.
- 맵 전체를 읽기 쉬운 카메라 구도.
- 캐릭터의 눌림과 튀어 오름, 낙하와 착지, 먼지와 타격 효과.
- 지형이 등장하고 사라지며 다음 공간으로 넘어가는 전환.
- 모놀리스의 상승, 선택 대상 강조, 캐릭터의 도약과 내려찍기로 표현되는 선택 확정.

메인과 로비, 결과에도 이 표현 방식을 이어갑니다. 모든 장면을 반드시 하나의 Unity 씬이나 거대한 맵으로 만들 필요는 없습니다. **플레이어가 같은 게임의 공간을 계속 이동한다고 느끼는 것**이 중요합니다.

**전체 흐름은 다음을 목표로 합니다.**

메인 → 방 만들기·참가 → 움직이는 로비 → 양쪽 준비 → 경기 ↔ 기존 모놀리스 선택 → 시상대 연출 → 자유 조작과 재시작 선택 → 새 경기 또는 메인

여기서 ‘메인 로비’는 방 만들기·참가 후 들어가는 온라인 대기 공간을 뜻합니다. 연습은 기존 로컬 플레이 흐름을 활용하며, 온라인 상대의 준비를 기다리지 않습니다. 모놀리스 선택은 현재 경기 규칙이 정한 시점에 진행합니다.

1. **메인 화면**

   현재 크게 표시되는 캐릭터를 살리고, 메뉴는 다음 구조로 구성합니다.

   | 상위 메뉴 | 하위 항목 |
   |---|---|
   | 게임 시작 | 방 만들기 / 코드로 참가 / 연습 |
   | 옵션 | 기본 설정 |
   | 게임 종료 | 게임 종료 |

   메인의 캐릭터, 바닥과 그림자, 메뉴의 등장 방식이 인게임 분위기와 이어지도록 구성합니다. 옵션과 코드 입력은 가독성과 조작 편의성을 유지하면서 게임 공간을 배경으로 보여주는 방향을 권장합니다.

2. **메인에서 온라인 로비로 진입**

   방 생성이나 참가가 성공하면 메인의 큰 캐릭터가 살짝 눌렸다가 위로 한 번 튀어 오르고, 아래로 떨어져 화면 밖으로 사라집니다.

   캐릭터가 보이지 않는 순간 로비 구도로 전환하고, 로비에서는 실제 플레이 캐릭터가 위에서 떨어져 착지합니다. 먼지와 몸의 눌림을 보여준 뒤 조작을 시작합니다. 하나의 도약과 낙하가 다른 공간의 착지로 이어지는 느낌을 목표로 합니다.

   연결이 준비되기 전에 캐릭터부터 사라지게 하지 않습니다. 연결 중에는 메인에서 상태를 표시하고, 실패하면 메뉴에서 다시 시도할 수 있어야 합니다.

   호스트는 먼저 로비에 들어와 움직입니다. 친구가 참가하면 호스트는 계속 움직이고, 새로 들어온 친구만 위에서 떨어져 등장합니다. 입장 연출 중인 캐릭터는 착지까지 공격에 방해받지 않도록 하는 방향을 권장합니다.

3. **움직일 수 있는 온라인 로비**

   혼자 기다리는 동안에도 이동하고 기본 조작을 연습할 수 있습니다. 친구가 들어오면 두 사람이 이동하고 기본 전투를 할 수 있습니다.

   방 코드와 복사 기능, 참가자와 준비 상태는 쉽게 확인할 수 있어야 합니다. **두 사람이 입장했다는 이유로 자동 시작하지 않고, 둘 다 준비 완료를 선택해야 경기가 시작됩니다.**

   로비에서는 체력바를 숨깁니다. 내부 체력과 타격·넉백·KO는 유지하며, KO되면 잠깐 뒤 정해진 위치에 체력을 회복한 상태로 다시 등장합니다. 점수나 승패는 발생하지 않습니다.

   준비 선택은 공격이나 넉백에 의해 바뀌지 않아야 합니다. KO되어 다시 등장해도 준비 상태를 유지하는 방향을 권장합니다. 준비 취소를 어디까지 허용할지는 세부 검토가 필요합니다.

4. **로비에서 경기 시작**

   둘 다 준비되면 시작 상태를 확정하고, 로비의 자유 조작을 잠근 뒤 경기로 전환합니다.

   로비의 체력 손실, 위치, 속도, KO 상태 등이 실제 경기에 넘어가지 않도록 경기 초기 상태를 설정합니다. 기존 맵 등장과 카운트다운 연출을 활용하고, 체력바와 경기용 표시를 다시 보여줍니다.

   현재 VS 연출을 그대로 유지할지, 첫 경기에서만 보여줄지, 짧게 조정할지는 검토할 항목입니다.

5. **경기와 모놀리스 선택**

   현재 전투와 모놀리스 선택의 분위기, 카메라, 효과, 조작과 규칙을 유지합니다.

   모놀리스 선택에 들어가는 시점과 선택 대상, 확정 방식도 기존 규칙을 기준으로 합니다. 이번 작업 때문에 모든 KO 후 모놀리스로 이동하는 식으로 경기 구조를 바꾸지 않습니다.

   주변 흐름을 이 구간에 맞추는 것이 목적이며, 카드 효과나 전투 밸런스의 추가·변경은 별도 범위로 다룹니다.

6. **결과·시상대 연출**

   최종 승부가 확정되면 결과 맵으로 전환합니다. KO로 사라진 패자도 결과 공간에 다시 나타나야 합니다.

   연출 순서는 다음 방향으로 정했습니다.

   **두 사람 조작 잠금 → 승자 아래 시상대 상승 → 승자의 짧은 자동 점프 → 착지 → 두 사람 자유 조작 해제**

   자유 조작 이후에는 서로 이동하고 공격하며 재시작을 기다릴 수 있습니다. 체력바는 로비처럼 숨깁니다. 확정된 승자와 최종 결과는 계속 확인할 수 있어야 합니다.

   결과 공간에서도 KO 후 다시 등장하는 규칙을 적용하는 것을 권장합니다. 승자가 나중에 얻어맞거나 떨어져도 이미 확정된 경기 결과는 바뀌지 않습니다.

   시상대는 상승이 끝난 뒤 고정된 발판으로 사용하는 안을 우선 검토해주세요. 아래에서도 접근할 수 있는 보조 발판을 두면 자유 조작 구간에서 함께 놀기 좋겠습니다.

7. **재시작과 나가기**

   각자 재시작을 선택하고, 누가 선택했는지 개별적으로 표시합니다.

   | 선택 상태 | 다음 동작 |
   |---|---|
   | 한 명만 재시작 선택 | 결과 공간에서 상대를 기다림 |
   | 두 명 모두 재시작 선택 | 같은 방에서 새 경기 시작 |
   | 한 명이라도 재시작 X 또는 나가기 선택 | 두 사람 모두 메인으로 복귀 |

   새 경기는 이전 경기의 점수·체력·선택 결과와 대기 공간의 상태가 섞이지 않도록 초기화합니다.

   ‘재시작 선택 취소’를 제공한다면, 두 사람을 메인으로 보내는 X와 의미를 구분해야 합니다. 로컬 연습은 한 사람의 선택으로 재시작합니다.

**메인 로비와 시상대는 모놀리스 선택 맵처럼 독립된 맵 데이터로 관리합니다.**

오브젝트도 기존 맵 수정기의 기능을 활용해 제작합니다. 수정기에서 편집한 형태와 배치가 실제 실행에 사용되는 구조가 목표입니다.

| 맵 용도 | 수정기에서 관리할 주요 내용 |
|---|---|
| 경기 | 기존 지형, 시작 위치와 설정 |
| 모놀리스 선택 | 기존 비석, 선택자 위치, 조명과 연출 설정 |
| 메인 로비 | 지형과 발판, 입장·재등장 위치, 장식 |
| 결과·시상대 | 시상대 형태, 승자·패자 위치, 상승 높이와 연출 설정 |

상자 크기 조절, 다각형 편집, 두 점 자르기, 스냅 등 현재 지원되는 기능을 재사용하고, 필요한 오브젝트 역할과 위치 표시를 추가하는 방향을 검토해주세요. 각 기능이 현재 지원하는 오브젝트 종류와 제약은 맵 제작 안내 및 코드를 기준으로 확인합니다.

로비와 결과 맵은 경기 랜덤 맵 목록에서 구분해야 합니다. 저장·불러오기·복제와 검증도 기존 제작 흐름 안에서 지원하면 좋겠습니다. 낙하와 시상대 상승을 확인할 미리보기가 필요하다면 그 범위도 제안해주세요.

**사전 조사에서는 다음 구조적 차이가 확인됐습니다. 구현 전에 현행 코드에서 재확인해주세요.**

| 현재 구조 | 필요한 검토 |
|---|---|
| 온라인 연결이 준비되면 경기 시작으로 이어짐 | 연결 완료, 로비 입장, 양쪽 준비, 경기 시작을 구분 |
| 현재 온라인 시뮬레이션 시작은 상대 참가를 전제로 함 | 호스트 혼자 있을 때도 로비에서 움직일 수 있는 구조 |
| 결과 상태에서는 전투가 멈추고, 재시작 준비가 공격 입력에 연결됨 | 결과 공간의 이동·공격과 재시작 의사를 독립적으로 처리 |
| 메인의 큰 캐릭터는 UI 초상으로 구성됨 | UI 캐릭터의 도약에서 실제 캐릭터의 낙하로 자연스럽게 연결 |
| 모놀리스 비석은 연출용 오브젝트로 취급됨 | 자유 조작 시상대에는 실제 발판 판정이 필요 |
| 맵 데이터에 보상 맵 구분이 있음 | 로비·결과 용도까지 확장하면서 기존 맵 보존 |

주요 확인 지점은 `FrontendController`, `OnlineLobby`, `OnlineMatch`, `FusionPredictionSession`, `FrontendInputSource`, `SimWorld`, `MapDefinition`, `MapAuthoringEditor`, `CardPickStage`, `FighterView`입니다. 구체적인 수정 파일과 새 구성 요소의 필요성은 실제 호출 관계를 확인한 뒤 제안해주세요.

온라인 처리에서는 다음을 검토해야 합니다.

- 준비와 재시작은 양쪽이 공유하는 명시적인 상태로 관리하고, 경기 시작은 한 번만 확정합니다.
- 지연된 이전 준비 입력이 다음 경기나 다른 단계에 적용되지 않도록 합니다.
- 로비·결과의 KO는 재등장으로 처리하는 안을 검토하고, 경기 점수와 승패 판정에 연결하지 않습니다. 로비의 KO 후 재등장은 합의한 방향이며, 결과 공간의 동일 규칙은 권장안입니다.
- 자유 조작 해제나 장면 전환 직후, 이전에 누르고 있던 버튼이 뜻하지 않은 공격·선택으로 이어지지 않도록 합니다.
- 실제 이동과 충돌에 쓰이는 로비·시상대 맵 데이터는 양쪽의 일치 여부를 검증합니다.
- 연결 종료를 모든 단계에서 처리하고, 상대를 무한히 기다리는 상태가 남지 않도록 합니다.
- 기존 전투 입력의 의미, 틱과 랜덤 소비, 온라인 결정론과 리플레이 호환성에 미치는 영향을 확인합니다.

시상대 상승 중에는 조작을 잠그고 연출을 보여준 뒤, 최종 발판과 캐릭터의 실제 위치를 맞추고 자유 조작을 여는 방식을 우선 검토해주세요. 실제 구현은 작업 규칙과 현행 개발 명세의 판정·표시 계층 구분을 따릅니다.

**옵션의 첫 범위는 현재 게임에 필요한 기본 항목을 제안합니다.**

- 음량 조절: 우선 현재 사용 중인 효과음 경로에 적용.
- 화면 모드와 해상도.
- 화면 흔들림과 강한 섬광을 줄이는 설정.
