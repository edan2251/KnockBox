1. 무충격: 기둥이 서 있고 지속 진동·자연 미끄러짐이 없음.
2. 약한 옆 충격: 받침과 접촉한 몇 층이 잠깐 함께 밀리거나 기울어짐. 반드시 붕괴할 필요는 없음.

자동 검증: 저장 왕복의 크기·질량·ID·순서 일치, 초기 낙하와 휴면, 세 충격 조건에서 접촉·변위·회전·속도·휴면·LooseTicks 기록, 단일 상자 비교, 동일 입력 반복·상태 복원, 기존 맵/리플레이 체크섬. 약/강 충격량과 허용 오차는 측정 후 정하고 근거를 기록합니다.

직접 검수: 같은 기둥을 초기화하며 무충격 → 약한 받침 충격 → 강한 받침 충격을 비교하고, 단일 상자의 밀림·회전도 확인합니다.

완료 기준: 제작·저장·시험 왕복과 세 반응 기준 충족. 보고에는 **기존 코드로 재현된 반응 / 실제 조정 항목 / 약·강 충격의 관찰 차이 / 단일 상자 영향**을 구분합니다. 손맛은 사용자 검수 전 확정하지 않습니다.

구현 결과: MapPhysicalBox/Handle과 전용 도구를 추가했습니다. 새 상자는 명시 질량과 깨어 있는 시작을 사용하며 새 데이터 맵만 전체 해시 schema 3·기록 v9를 사용합니다. 11-10 피드백은 별도 상태 필드 없이 기존 LooseTicks를 재사용하며 설정 해시로 구 반응과 구분합니다. 구분선 제거와 삭제/Undo 직후 Inspector 참조 오류도 수정했습니다. 최초 216개 통과 기록과 피드백 회차의 고유 160개 통과 결과는 별도로 [PROGRESS](progress/PROGRESS.md)에 보존합니다.

2026-11-10 앞선 피드백: 사용자가 `CP3_Rope_Graph_Trial`의 연결 상자 위에서 빠른 떨림과 피해를 보고했습니다. 모서리 접촉점과 하중 적용 순서를 재현 후 보완했습니다. 일반 상자/기둥 값과 과거 계산 경로를 유지하며 기존 효과 풀·타격음·카메라를 재사용했습니다. 최신 근거와 검수 한계는 PROGRESS의 첫 항목을 봅니다. CP5는 착수하지 않습니다.

주요 변경은 MapRope/Handle·MapRopeTools, ArenaDef의 조건부 geometry schema 7, RopeGeometry/RopeConnectors와 PropView입니다. 저장·재열기·복제/대칭·Undo·Main 미등록 시험 전달, 실제 차징/던지기 경로·속도 85%·경직 없음, 표시/판정 위치, 360틱 기록/복원 및 손실 네트워크를 확인했습니다. 이번 고유 검사 384개는 최종 통과이며 중간 실패·수정·재검사는 [PROGRESS](progress/PROGRESS.md)에 분리했습니다.

직접 검수는 [CP3_Rope_Connector_Trial](../../Assets/_Project/Data/Maps/Validation/CP3_Rope_Connector_Trial.asset)에서 진행합니다. 왼쪽 일반 줄 유지, 오른쪽 연결부의 세 공격 파괴, 점프/걷기 통과와 감속을 비교합니다. [검수 절차](../team/PLAYTEST.md#6-공격으로-부서지는-로프-연결부)를 따르며 CP5는 별도 승인 전 대기합니다.

### 최초 당김 파단 구현 기록

아래는 후속 규칙 변경 전 CP3 기록입니다. 일반 줄/공격 연결부의 현재 규칙은 위 내용을 적용하고, 기존 당김 시험 자산은 그대로 보존합니다.

상태: **구현·자동 검사 완료 / CP4와 함께 사용자 Play 검수 대기**. 후속 저장 장애는 로프 길이 부족의 구체적 안내와 안전한 길이 보정으로 수정했으며 관련 72개 검사를 통과했습니다. 사용자는 아직 로프 Play 시험을 하지 않았습니다. MapRope/MapRopeHandle, MapRopeTools, PropPhysics의 새 당김 경로, RopePath와 PropView에 연결했습니다. 로프가 실제 가한 충격량을 틱 시간으로 나눈 힘으로 비교하며 기본 파단 힘 600은 Inspector에서 조절하는 시험값입니다. 느슨함·정상 하중·약/강 당김·파단 불가, 복제/대칭/Undo, 저장·재열기·Main 전달과 구 로프 기대 해시를 검사했습니다. 시험 맵과 결과는 [PROGRESS](progress/PROGRESS.md), 조작은 [팀 안내](../team/TEAM_WORKFLOW.md#독립-로프)에 있습니다.

선행: CP2·CP2-1의 상자 ID·질량·상태 구조 확인과 사용자 진행 승인. 목표: 맵 고정점에서 상자 하나를 연결하는 독립 로프 제작.

변경 영역: 로프 정의·에디터 핸들, PropDef 연결 변환·PropPhysics 제약 해석·파단 상태, 표시, 저장·복사·맵 해시·구 리플레이 분기.

- 고정점·상자 로컬 연결점·길이·파단 가능 여부·강도를 저장합니다. 로프는 상자 ID를 참조하며 상자 안에 암묵적으로 저장하지 않습니다.
- 느슨한 로프는 파단하지 않고 평상시 하중을 지탱합니다. 팽팽할 때 실제 전달된 당김을 기준으로 파단하며, 끊긴 상자는 기존 속도·회전을 이어받습니다.
- 상자+로프 복사·좌우 대칭은 새 ID를 만들고 새 상자를 가리키게 합니다. 누락 참조·중복 연결·잘못된 길이를 검증합니다.

자동 검증: 느슨함/정적 하중/약한 당김/강한 당김/파단 불가 비교, 파단 틱 재현, 파단 직전·직후 상태 저장/복원·체크섬, 구 로프 리플레이, 복사 참조와 저장 왕복.

직접 검수: 매달린 상자 흔들기 → 약한 당김 유지 → 강한 당김 파단 → 속도·회전을 이어 낙하, 복제/대칭한 세트 시험.

완료 기준: 같은 입력의 파단 틱과 상태가 같고, 상자가 독립 낙하하며 구 맵 결과가 유지됩니다. 직접 로프 피해·몸체 하나에 여러 로프는 제외합니다.

## CP4. 고정 볼록 지형과 두 점 절단

상태: **구현·자동 검사 완료 / 사용자가 절단 기능이 잘 작동한다고 피드백함**. 사선 충돌·모든 배치까지 직접 검수가 끝났다고 확대 해석하지 않습니다. 고정 Solid 지형의 3~32개 볼록 꼭짓점을 표시·파이터 충돌·물리 상자 접촉·그림자·손발 질의에서 함께 사용합니다. MapTerrainCut의 미리보기·남길 쪽 전환·취소·1회 Undo/Redo·반복 절단·저장 왕복을 구현했습니다. 사각 지형의 기존 계산과 기대 해시는 보존합니다. 새 경사는 약 45도까지 보행하며 더 가파른 면은 미끄러지는 초기 기준입니다. Play 손맛 검수 후 필요하면 별도 조정합니다. 사용법은 [팀 안내](../team/TEAM_WORKFLOW.md#고정-지형-두-점-절단)에 있습니다.

선행: CP2·3의 맵 데이터/호환 경계 고정. 큰 변경을 승인 단위 안에서 두 묶음으로 검증합니다: 먼저 다각형 표시·충돌, 다음 절단 UI.

변경 영역: MapDefinition/ArenaDef의 선택적 꼭짓점 데이터, TerrainCollision·지형 질의·파이터 지지/벽/천장·상자 접촉, 맵 표시·그림자, 절단 도구와 저장·Undo. 휴면 중인 무기/총알의 새 다각형 대응은 개발하지 않습니다.

- 사각형은 기존 경로를 유지합니다. 새 고정 지형은 판정과 표시가 같은 볼록 꼭짓점 배열을 사용합니다. 경사면 걷기·벽·모서리 기준은 기존 접촉 법선을 먼저 재사용하고 변경 영향부터 검사합니다.
- 선택 지형의 경계 두 점을 지정합니다. 꼭짓점·변 중간 모두 가능하며 절단선과 제거 영역을 미리 봅니다. 남길 쪽 전환·취소·한 번 Undo·반복 절단을 지원합니다.
- 윗변 중간→오른쪽 변 중간으로 우상단 모서리만 제거할 수 있어야 합니다. 남은 도형의 기존 ID·판정 순서를 유지합니다. 점 순서·정밀도·퇴화/오목 결과를 검증합니다.

자동 검증: 사각 맵/리플레이 기준값 불변, 사선 표시와 실제 꼭짓점 일치, 경사 접촉·스폰 검증·상자 접촉·그림자, 모서리 절단·양쪽 선택·취소·Undo/Redo·반복 절단·저장 왕복·결정론.

직접 검수: 모서리 절단 미리보기·남길 쪽 전환·취소·Undo, 반복 절단 저장·재열기, 실제 파이터/상자가 사선에 맞게 서고 미끄러지는지 확인.

완료 기준: 표시만 기울고 충돌이 사각형으로 남는 경우 없음. 무기 구 리플레이는 구 맵 경로로 보존하며 새 맵+구 무기 설정 조합의 지원 범위를 명시합니다.

## CP5. 통합 검증과 팀 안내

상태: **완료 — 2026-11-10 자동 검사 384개 통과, 2026-11-11 사용자 Unity Play 검수 완료 승인**. 최신 승인 범위는 제작기 버튼 정리·새 로프 UI 단순화·색상 반영과 통합 검사입니다. 과거 파단 데이터·기존 시험 맵은 보존합니다. 최신 결과는 [PROGRESS](progress/PROGRESS.md)에 기록합니다. 실제 2PC Relay와 새 Player 빌드는 검증하지 않았습니다.

완료 기준: 자동 결과·사용자 검수·미검증을 분리해 최종 인계. 두 PC Relay 실기는 보류로 남깁니다.
