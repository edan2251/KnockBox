# 작업 결과 기록 양식

새 기록은 이 양식을 참고해 `docs/ai_docs/progress/`에 작성합니다. 제목과 파일명에는 작업 내용과 날짜를 넣고, [문서 안내](../../../README.md)에서 찾을 수 있도록 연결합니다. 실제 작업 권한과 검증 원칙은 [작업 규칙](../../WORKING_RULES.md)을 참조하며 여기서 반복하지 않습니다.

## 작업 목적과 범위

사용자가 요청한 문제와 이번에 다룬 범위를 짧게 씁니다. 시작 위치·브랜치·기준 커밋, 기존 미커밋 파일과 백업 위치를 구분해 적습니다.

## 실제 변경

어떤 파일을 왜 바꾸었고 사용자가 보는 동작이 어떻게 달라졌는지 설명합니다. 새 파일·클래스·추상화를 추가했다면 맡은 책임과 기존 코드로 해결하지 않은 이유를 한 줄로 적습니다. 코드가 바뀌었다면 관련 명세·주석·사용 안내를 확인한 결과도 적습니다. 게임 규칙·입력·온라인·리플레이 영향이 있으면 따로 적습니다. 계획했지만 수행하지 않은 것은 이 절에 넣지 않습니다.

## 검증 결과

[변경별 검사](../../../team/TEAM_WORKFLOW.md#변경별-검사)에서 고른 검사와 이유, 변경 전 실행 여부를 먼저 적습니다. 실행하지 않은 검사는 미실행으로 남깁니다.


예: 해당 화면 재실행

방법과 대상: Main에서 구체적인 순서

실제 결과: 통과 / 실패 / 미실행

근거: 로그·테스트 이름 등


처음 실패했다면 원인과 수정 후 결과를 구분합니다. 예전 통과 결과를 인용할 때는 날짜와 원래 기록을 연결합니다. 화면·조작감·다른 PC 시험처럼 직접 확인하지 않은 내용은 미확인으로 남깁니다.

## 사용자가 직접 확인할 순서

열 씬이나 파일, 누를 버튼, 기대되는 결과를 순서대로 적습니다. 영상과 스크린샷은 필요한 경우에만 연결합니다.

## 남은 문제와 다음 작업

기존 실패·새 실패·보류·미검증을 구분하고, 다음에 확인할 작업과 사용자 결정이 필요한 사항을 적습니다. 승인받지 않은 후속 계획을 완료로 표현하지 않습니다.
