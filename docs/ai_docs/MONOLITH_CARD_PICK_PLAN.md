# 모놀리스 카드 선택 연출 기획

기준: 논의는 2026-11-12(main `ac39c2b`), 온라인·폼 제거 관련 설명은 2026-11-13에 main `cc979e0`(Photon Fusion 3틱 롤백 적용 후) 기준으로 고쳤습니다. **기획 논의 결과를 정리한 문서이며 이 문서 자체는 개발 승인이 아닙니다.** 개발 범위와 승인은 [PROGRESS](progress/PROGRESS.md#현재-승인-범위)에 따로 기록합니다. 아래 "확인한 현재 구조"는 2026-11-12에 코드를 읽어 확인한 내용이고, "확정"은 사용자와의 논의에서 정한 방향입니다. 2026-11-13에 승인된 0~2단계(선택 맵·모놀리스 표면·클릭 선택, 호버 점등·광원·대기 캐릭터·디자인 정리)를 구현했으며 결과는 [개발 진행](#개발-진행)에 적습니다. 시뮬레이션 설정·상태·입력 형식은 바꾸지 않았습니다. 2단계 화면은 아직 사용자 Play로 확인하지 않았습니다.

## 목표

세트 패자가 카드를 고르는 화면(지금은 UI 클릭)을 **게임 안의 장면**으로 바꿉니다. 라운드 사이에 경기장이 사라지고 바닥만 있는 별도의 선택 맵이 나타나며, 거대한 모놀리스 3개 중 하나를 호버·클릭해 카드를 고릅니다. 카드는 나중에 수십 종의 파워업으로 늘어나므로 모놀리스는 **어떤 카드든 같은 틀로 그리는 템플릿**이어야 합니다.

## 확인한 현재 구조

- 카드 선택은 `FrontendView*`의 UI 클릭을 `FrontendInputSource.Choose(option)`이 기존 선택 버튼 비트로 바꿔 시뮬레이션에 전달합니다. 온라인은 락스텝이 아니라 호스트가 판정하는 Fusion 예측 구조(입력 지연 3틱)입니다. 화면은 예측 월드(`runner.World`)로 그리고, 카드 UI와 일회성 연출은 확정 월드(`runner.FrontendWorld`)를 읽습니다. 모놀리스의 호버·클릭은 같은 `Choose`를 호출하면 되고, **모놀리스의 상태는 확정 월드에서 읽어야 합니다.**
- 고르는 사람은 세트 패자 한 명(`Picker`)입니다. 선택지는 `CollectCardsOnly`에서 항상 3개(`CardCollectionRules.CardCount`)이고 지금은 한 방·맷집·멀리 던지기이며 능력 효과는 없습니다.
- 시간 초과(`PickTimeoutTicks = 900`)이면 시뮬레이션이 무작위로 고릅니다. 확정 뒤 대기는 `PickHoldTicks`이며 연출 모드에서 144틱입니다(2026-11-14 4b 승인으로 84틱에서 늘림).
- 그림자는 한 점 광원에서 뻗는 메시(`ProjectedShadowMesh`)이고 `ProjectedBackground.shader`가 그립니다. **그림자가 겹쳐도 진해지지 않고(`Blend One Zero`), 길이(`reach`)가 화면 끝을 넘어갑니다.** 그림자 진하기는 상수(`ShadowStrength = .65`)입니다. 배경 밝기는 광원 거리에 따른 감쇠(`Falloff`)를 기준 광원(`_BaseLight`)과의 비율로 계산합니다.
- `BackgroundView.SetLight(Vector2)`는 배경 질감을 다시 굽지 않고 그림자 메시만 다시 투영합니다. 광원을 움직이는 것은 이미 되는 구조입니다. 사각형과 볼록 다각형(사다리꼴 포함) 그림자를 지원합니다.
- 경기장 소멸·재구성 효과(`CardCollectionRules.RebuildTicks` 등)와 라운드 광원 점등(`SetRoundLight`, `SetRoundLightPulse`)이 있습니다.
- 가위바위보 초기 폼 선택과 옛 선택 화면 `PickPanelView`는 2026-11-11 폼 전투와 함께 삭제했습니다.

## 확정한 연출

### 화면 구성

- 바닥만 있는 별도 선택 맵입니다. 경기장이 사라진 뒤 이 맵이 구성되고, 끝나면 기존 경기장 재구성 효과로 다음 경기장이 돌아옵니다. 그림자를 받을 약한 배경막은 유지합니다.
- 고르는 패자 캐릭터는 **자기 프로필 위치(좌 또는 우)** 에 서고 모놀리스 3개는 그 **반대편**에 놓입니다. 승자 캐릭터는 화면에 나오지 않습니다. 패자가 항상 왼쪽에 있는 것은 아닙니다. **승자도 패자와 같은 화면을 봅니다.** 패자의 호버(비석 점등·어두워짐, 캐릭터 눈)가 승자 화면에도 그대로 보입니다(2026-11-13 확정). 광원은 호버로 움직이지 않습니다. 옛 선택 화면의 "선택 중 내용을 상대에게 숨긴다"는 방침은 이 기획에서 따르지 않습니다.
- 모놀리스는 **화면 안에 윗부분이 보이는 비석**입니다(2026-11-14 방향 수정, 이전의 "화면을 넘길 만큼 거대한 기둥"을 대체). 높이는 화면 높이의 약 75~85%, 폭은 캐릭터 몸의 8~9배 안팎입니다. 바닥에 평평하게 서고 위 두 모서리를 깎고 위를 살짝 좁힌 볼록 다각형이며, 세 개의 높이(가운데가 가장 높게)·폭·간격을 조금씩 다르게 합니다. 도형은 기존 게임의 기하학만 씁니다.

### 모놀리스 표면 (카드 데이터가 채우는 틀)

카드 면은 비석 몸체에 새겨진 것처럼 몸체와 한 덩어리이고 몸체의 대부분을 차지합니다. 위에서 아래로 **그림 영역 → 이름 띠 → 어두운 텍스트 패널**입니다. 이름이 그림과 설명을 나눕니다. 보유 개수 표시와 효과 수치 줄을 위한 칸을 비워 둡니다.

- 그림 영역: 카드 아이콘 한 개.
- 이름 띠: 카드 이름. 켜지면 이름이 노란 강조색이 되고 띠가 살짝 커집니다.
- 텍스트 패널: 설명과 효과 줄. 긍정은 연두, 부정은 빨강, 중립은 흰색으로 구분합니다. 글자는 PC 기준 최소 9 글자 크기에서 읽혀야 하므로 **줄당 글자 수와 줄 수를 카드 데이터 규칙으로 제한**합니다.
- 상태(꺼짐·어둡게·켜짐)는 면·몸체의 발광과 어두워짐으로 읽습니다. 처음 계획의 모서리 꺾쇠는 방향 수정에서 뺐습니다.

### 상태 3단계

1. **처음 등장:** 빈 비석이 솟고, 플레이어 색 기운이 걷히며 카드 내용이 **어둡게** 드러납니다(2번과 같은 실루엣 상태, 2026-11-14 사용자 피드백). 비석 윤곽은 배경과 구분됩니다.
2. **한 번이라도 호버한 뒤:** 호버하지 않은 비석은 ROUNDS처럼 **거의 검은 실루엣**이 되고, 글자는 흐리게라도 읽힙니다.
3. **호버:** 그 비석의 **카드 면 전체가 켜집니다.** 그림 영역은 밝은 황금색으로 차오르고(옅은 사선 무늬), 이름은 노란 강조색, 텍스트 패널은 어두운 바탕을 유지합니다. 몸체도 함께 밝아집니다. 외곽선 빛줄기가 아니라 면과 몸체의 발광이며, 켜질 때 아래에서 위로, 꺼질 때 위에서 아래로 부드럽게 바뀝니다.
- 호버한 비석 아래 바닥의 빛 번짐(하이라이트)은 만들지 않습니다. 별도 접촉 띠도 두지 않습니다(바닥에 바로 서고 그림자를 드리운다).
- 원근: 가장 높은 비석을 앞으로 보고, 낮은 비석일수록 꺼진 상태 색을 자동으로 조금 어둡게 합니다. 켜진 비석에는 보정을 주지 않습니다.

### 광원 — 패자 캐릭터 위 고정 광원

- 광원은 **고르는 패자 캐릭터 바로 위**(캐릭터와 같은 x, 화면 위쪽)에 고정합니다. 고르는 사람이 P2면 광원도 P2 위로 와서 좌우가 뒤집힙니다(2026-11-14 방향 수정, 이전의 "B+A 조합"을 대체).
- 호버해도 광원은 움직이지 않습니다. 전달된 상대 호버도 점등·어두워짐·눈 방향에만 씁니다.
- 그림자는 기존 경기와 같은 방식(같은 셰이더·재질·진하기 0.65, 직선 윤곽이 화면 끝까지, 겹쳐도 진해지지 않음)으로 이 고정 광원에서 비석 셋 모두 드리웁니다.

### 대기 중 캐릭터

패자는 자기 위치에서 대기합니다. 눈이 호버한 모놀리스를 따라가고 몸이 살짝 기울며 가벼운 숨쉬기 정도의 움직임만 줍니다. 마주 보는 구도는 아닙니다. 그 밖의 추가 연출(배경 입자 등)은 이번 범위에 넣지 않습니다.

### 타임라인

1. **전환:** 경기장이 사라지고 바닥만 남습니다(기존 소멸 효과).
2. **솟아오름:** 선택 맵이 구성되고 모놀리스 3개가 바닥에서 차례로 솟아오릅니다. 낮은 울림, 짧은 흔들림, 먼지, 가벼운 광원 깜빡임을 줍니다. 진입 연출은 교체 가능한 모듈로 두어 나중에 "하늘에서 쾅쾅쾅 박히는" 안으로 바꿀 수 있게 합니다.
3. **대기:** 위 상태·눈 움직임대로 호버를 받습니다(광원은 고정). 시간 초과 시 시뮬레이션이 고른 것으로 확정합니다.
4. **확정:** 패자 캐릭터가 웅크렸다가 **크게 점프해 선택한 모놀리스를 땅으로 내리찍습니다.** 쫀득하게 만들기 위해 스쿼시·스트레치, 정점의 짧은 체공, 충돌 순간의 짧은 정지, 카메라 흔들림, 바닥 충격파를 씁니다. 모놀리스는 오버슈트를 두고 바닥에 박히며 라운드 광원 펄스(`SetRoundLightPulse`)를 재사용합니다.
5. **흡수:** 모놀리스가 박히는 동시에 아이콘·이름 조각이 점으로 흩어져 캐릭터에 흡수됩니다. KO 뒤 점이 점수판으로 이동하는 기존 문법을 따릅니다.
6. **정리:** 선택되지 않은 2개는 꺼진 채 두고, 맵이 사라질 때 함께 사라집니다.
7. **복귀:** 기존 경기장 재구성 효과를 그대로 재사용합니다.

## 개발 때 결정하거나 확인할 것

2026-11-13 코드 확인과 사용자 결정으로 1~8번을 정했습니다. 9번은 2단계 계획에서 제안합니다.

1. **확정 연출 길이와 `PickHoldTicks`:** 값은 `CardCollectionRules.Apply`의 연출 모드에서 84틱이며 설정 체크섬에 들어갑니다. 처음에는 84틱 안에 압축했으나, 2026-11-14 사용자 Play에서 서두르는 느낌이 나서 **4b를 승인받아 144틱(2.4초)으로 늘렸습니다.** `CardCollectionRules.Apply(longPickHold)`로 새 경기만 144틱을 쓰고, 그 전 기록은 리플레이 설정 후보(84틱)로 그대로 재현합니다. 설정 체크섬이 달라지므로 온라인 접속 버전 문자열에 `-hold144`를 붙였습니다. 온라인 클라이언트는 확정 월드가 예측 월드보다 약 왕복 지연만큼 늦으므로, 확정 연출 끝부분이 다음 경기장 재구성과 겹칠 수 있습니다.
2. **캐릭터 연출의 위치:** KO·SetPick 동안 시뮬레이션은 파이터를 갱신하지 않습니다. 패자는 `Action=KO`, 체력 0 이하, `HitstopTicks`도 KO 값 그대로 멈춰 있습니다. 그래서 선택 화면의 패자는 선택 맵의 시작 위치로 만든 **표시 전용 상태**로 그립니다(1단계 구현). 점프·내리찍기도 같은 방식으로 표시 위에 얹습니다.
3. **카드 수십 종에서 3장 뽑기:** **이번 범위에서 제외**했습니다. `BuildOptions`는 난수를 쓰지 않고 3종을 고정합니다. `s.Rng`로 뽑으면 시간 초과 선택과 재대결 맵 섞기의 난수 순서가 바뀌므로, 나중에 시뮬레이션 규칙 변경으로 따로 승인받습니다.
4. **카드 데이터 구조:** 시뮬레이션의 `AugmentDef`와 분리한 **카드 표시 목록**(`CardFaceCatalog`, 카드 Id 기준)을 만들었습니다. 아이콘은 기존 도형 조합(`ShapeLibrary`)으로 그립니다. 나중에 교체할 스프라이트 칸은 비워 두었습니다. 현재 세 카드의 문구는 효과가 없어 "임시"를 표시한 레이아웃 시험용입니다. 희귀도 표시는 아직 없습니다.
5. **선택 맵 만드는 방법:** **미등록 보상 맵 `MapDefinition`**(`Data/Maps/CardPick/CardPick_Stage`)입니다. MapAuthoring에서 편집하되 GameMaps에 등록하지 않습니다. 바닥(지형)·비석 3개·패자 자리·장면 값을 이 맵 파일 하나에 저장합니다(아래 "보상 맵 편집"). P2가 고르면 모두 좌우로 뒤집습니다.
6. **광원 값:** 2026-11-14 방향 수정으로 호버 광원 이동을 폐기했습니다. 패자 위 고정 광원의 "캐릭터 위 높이"와 "좌우 오프셋"만 보상 맵의 장면 값에 노출하고 실제 화면에서 맞춥니다.
7. **모놀리스 표면 글자 렌더링:** **월드 공간 uGUI `Text`**와 기존 한글 폰트를 씁니다. TMP 에셋은 추가하지 않습니다. 1280×720 확인 캡처에서 설명 글자가 약 13px였으므로 1080p에서는 약 20px로 추정합니다. 9 글자 크기 기준 판독은 사용자 Play로 확인합니다.
8. **참고 영상:** 사용자가 보내준 ROUNDS 카드 선택 장면(꺼진 카드, 호버 시 점등, 호버하지 않은 카드는 그림만 어두워짐, 이름·효과 줄 색 구분)을 참고했습니다. 영상 자체는 AI가 볼 수 없어 사용자가 보낸 스크린샷 3장만 근거로 삼았습니다. 상태 표현 방식만 참고하고 외형은 이 게임의 도형으로 새로 만듭니다.

9. **패자의 호버를 승자 화면으로 전달:** [호버 전송](#호버-전송2b)대로 구현했습니다. 원래 확인 항목: 호버는 시뮬레이션 입력이 아니므로 `InputFrame`·`SimState`·입력 기록에 넣지 않고, 표시 전용으로 별도 전송해야 합니다. 현재 Fusion 구조에서 보낼 수 있는 방법(손실을 허용하는 가벼운 전송인지), 전송 빈도, 지연이 있을 때 승자 화면의 보간, 오프라인 로컬 연습에서의 처리를 먼저 확인합니다. 호버 값이 늦거나 끊겨도 확정 연출은 확정 월드(`PickedAt`)를 기준으로 진행해야 합니다.

## 보존할 것

- 호버 정보가 시뮬레이션 상태·입력 형식·체크섬·리플레이에 들어가지 않게 합니다. 기록을 다시 재생하면 호버 없이 확정 결과만 재현됩니다.
- 시뮬레이션의 전투 규칙, 틱과 랜덤 소비 순서, 온라인 결정론과 리플레이 호환은 바꾸지 않습니다.
- 기존 카드 선택 UI와 `FrontendInputSource.Choose` 경로는 모놀리스 구현이 대체하기 전까지 지우지 않습니다.
- 경기 판정을 Unity 물리로 대체하지 않습니다.

### 확정 연출(4단계)

확정 대기(`PickHoldTicks`, 연출 모드 144틱 = 2.4초)에서 퇴장 0.35초를 뺀 약 2.05초 안에 끝냅니다(기준값을 약 0.97배로 거의 그대로 씀). 대기가 짧은 모드(42·54틱)는 전체를 비율대로 줄입니다. 시간은 확정 월드의 `PhaseTick − PickedAt`에서 계산하므로 승자 화면·늦게 들어온 화면도 같은 순간을 보고, 시간 초과로 무작위 선택된 경우도 같습니다. 연출은 시뮬레이션에 쓰지 않습니다.

4. 인스펙터 "보상 맵 · 카드 선택 장면"에서 장면 값(광원 높이·좌우 오프셋, 원근, 점등 시간, 기울기·숨쉬기, HUD)을 바꿉니다.

6. 확인은 Main Play에서 연습을 시작해 세트를 진 뒤에 합니다. "저장한 맵으로 시험"과 GameMaps 등록은 보상 맵에서 막혀 있습니다.

### 2c에서 정리한 것

- **호버 광원 이동 제거:** 당시 `Card_Pick_Stage`의 호버 광원 위치·따라가는 빠르기·기준 쪽 비율·위끝 여백·환경광 값과 그 계산을 지웠습니다.

- **그림자 재질:** 모놀리스 그림자 전용 재질(진하기 0.3)을 없애고 경기 그림자 재질을 그대로 씁니다. "호버한 비석은 그림자를 드리우지 않음" 규칙도 없앴습니다.
- **외형 정리:** 외곽선 빛줄기와 모서리 사선 표시(옛 꺾쇠)를 지웠습니다. 라벨의 이름판 배경과 시간 원판도 지웠습니다.

### 디자인 정리(1단계 지적 사항)

1. **카드 면이 몸체와 다르게 삐뚤어짐**
   - 원인: 1단계 몸체는 위로 좁아지는 사다리꼴이었는데 카드 면은 직사각형이었습니다. 여기에 모놀리스 전체를 1.2°·−0.8° 기울여서, 한쪽 변은 기울기와 좁아짐이 상쇄되고 반대쪽은 더해졌습니다.
   - 수정: 몸체·외곽선·카드 면·이름 띠·패널을 같은 윤곽 함수로 만들어 옆변이 평행하게 했습니다. 기본 기울기는 0으로 두고, 값(회전)은 남겼습니다.
2. **윤곽:** 몸체와 카드 면의 모서리를 깎고 위로 살짝 좁혔습니다. 모든 윤곽은 반시계 볼록 다각형이며 `ConvexPolygon`으로 검사합니다.
3. **테두리의 이상한 강조:** 원인은 두 가지였습니다. 2c에서 사선 표시도 지웠습니다.
   - (a) 카드 면 바깥에 떠 있던 L자 꺾쇠(1단계 산출물, 계획의 상태 표시)입니다. 깎인 모서리를 따라가는 사선 표시로 다시 디자인했습니다.
   - (b) 색 번짐은 화면 색수차(PostFx)입니다. KO 때 생긴 펄스가 시뮬레이션이 멈춘 동안에는 줄지 않아 남습니다. 실제 진행 중에는 0으로 돌아오며, 제거할 잔여물은 아닙니다.
4. **윗부분의 띠:** 재현하지 못했습니다.

### 호버 전송(2b)

2026-11-13 사용자가 아래 제안을 승인해 구현했습니다. 구현 위치: 전송 규칙 `CardHoverRelay`(Game/Online, 네트워크와 분리), RPC `FusionConnection.Rpc_CardHover`, 연결 `OnlineMatch.CardHover`, 표시 `CardPickStage`.

- **방법:**
  - `FusionConnection`에 표시 전용 비신뢰 RPC를 하나 추가합니다(`Rpc_CardHover`). 기존 `Rpc_LockstepFragment`와 같은 방식입니다.
  - 내용은 라운드 번호(ushort)·순번(ushort)·호버한 선택지 번호(sbyte, −1 없음)로 5바이트입니다. 모놀리스 칸이 아니라 선택지 번호로 보내 좌우 반전과 무관하게 합니다.
  - 입력(`FusionPlayerInput`)·확정 기록·`SimState`·체크섬·리플레이에는 넣지 않습니다.
  - 입력 경로를 쓰지 않는 이유: Fusion 입력은 클라이언트에서 호스트로만 가므로, 호스트가 패자일 때 승자(클라이언트)에게 전달되지 않습니다.
- **빈도:**
  - 고르는 사람이 로컬일 때만, 호버가 바뀌는 즉시 보냅니다.
  - 바뀌지 않아도 0.25초마다 같은 값을 다시 보내 손실을 메웁니다. 변경 사이 최소 간격을 0.05초로 두어 초당 최대 약 20회로 제한하고, 확정(`PickedAt`) 뒤에는 보내지 않습니다. 클릭한 뒤 확정 전까지는 고른 모놀리스를 계속 보냅니다.
- **수신과 지연:**
  - 순번이 커진 것만 받고, 라운드가 다르거나 확정 뒤에 온 값은 버립니다.
  - 받은 값은 로컬 호버와 같은 점등·광원 이동으로 부드럽게 따라가므로 별도 보간이 필요 없습니다. 승자 화면은 대략 편도 지연만큼 늦게 따라갑니다.
  - 0.75초 넘게 소식이 없으면 호버 없음으로 돌아갑니다(점등은 0.2초에 걸쳐 꺼짐).
  - 확정 표시는 늘 확정 월드를 따르므로, 호버 값이 늦거나 끊겨도 결과는 같습니다.
- **오프라인:**
  - 로컬 연습은 같은 PC라 전송 없이 그대로 보입니다. 연습 봇이 고를 때는 호버가 없습니다. 원하면 봇이 고르기 전에 잠깐 훑는 표시 전용 호버를 추가할 수 있습니다(별도 결정).
  - 기록 재생에는 호버가 없고, 확정 결과만 재현됩니다.
