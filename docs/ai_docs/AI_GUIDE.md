# AI 참고 안내

AI가 안내를 찾는 위치와 작업 전에 읽을 문서를 설명합니다. 실제 작업 규칙은 [WORKING_RULES.md](WORKING_RULES.md) 한 곳에서 관리합니다.

<a id="작업을-시작할-때"></a>

## 작업 시작 순서

1. 루트 지시 파일을 통해 [현재 작업 규칙](WORKING_RULES.md)을 읽습니다.
2. 실제 프로젝트·Git 루트, 브랜치, 미커밋 상태를 확인합니다. 원본과 새 프로젝트가 함께 있으므로 경로를 추측하지 않습니다.
3. [문서 안내](../README.md)에서 작업 분야를 고르고, [진행 현황](progress/PROGRESS.md)의 현재 상태와 현재 승인 범위를 확인합니다. 관련 상세 기록은 연결된 상시 문서와 보관 목록에서 찾습니다.
4. 편집 작업은 [팀 안내](../team/TEAM_WORKFLOW.md)나 [아트 안내](../team/ART_WORKFLOW.md)를 읽습니다. 판정 변경을 조사한다면 [현행 개발 명세](CURRENT_DEV_SPEC.md)와 관련 코드를 읽습니다.
5. 과거 판단의 근거가 필요할 때만 요청서·명세·[보관 목록](HISTORY.md)에서 관련 자료를 찾습니다.

온라인 연결·카드 능력·카드 선택 연출을 다루는 작업이면 [온라인 개발 기준](ONLINE_MULTIPLAYER.md)을 직접 읽습니다. 현재 서버 구조·기본 3틱 정책·코드 지도·예측/확정 경계·카드 확장 계약을 확인합니다. 구조 변경 후에는 이 문서를 코드에 맞춰 갱신하고 실제 검사 결과는 PROGRESS에 남깁니다. 과거 구현 경위는 [보관 안내](HISTORY.md)를 확인합니다. 링크 자체가 문서를 자동으로 읽어 주지는 않습니다.

문서 전체를 매번 다시 읽을 필요는 없습니다. 다만 과거 절차를 현재 승인으로 재사용해서는 안 됩니다.

<a id="도구가-자동으로-찾는-파일"></a>

## 도구별 자동 인식 파일

두 도구가 찾는 파일과 상세 규칙을 읽는 방식은 다릅니다.


Codex

프로젝트 진입점: 루트 `AGENTS.md`

상세 규칙을 읽는 방식: 상세 파일을 직접 읽으라는 지시와 링크를 둡니다. 일반 Markdown 링크는 자동 import되지 않습니다.


Claude Code

프로젝트 진입점: 루트 `CLAUDE.md`

상세 규칙을 읽는 방식: `@docs/ai_docs/WORKING_RULES.md` 문법으로 현행 규칙을 import합니다.


**Codex:** 프로젝트 루트에서 현재 작업 디렉터리까지 적용되는 `AGENTS.md`를 확인합니다. 더 가까운 디렉터리의 지침은 해당 범위에 추가로 적용될 수 있습니다. `AGENTS.override.md`가 있으면 우선할 수 있습니다.

**Claude Code:** `CLAUDE.md`, `.claude/CLAUDE.md` 등 정해진 위치의 프로젝트 메모리를 읽습니다. `@` import에는 그 파일을 기준으로 한 상대 경로를 사용할 수 있습니다.

따라서 루트에는 짧은 진입점 파일을 유지합니다. 이 파일을 `docs` 안으로 옮기기만 하면 자동 인식을 보장할 수 없습니다. 팀 규칙의 별도 사본을 사용자 홈이나 도구별 파일에 만들지 않습니다.

로컬 사용자 지시나 하위 디렉터리의 지시 파일이 추가되었다면, 실제 적용 범위를 다시 확인합니다.

인식 방식은 **2026-11-06 확인 기준**입니다. 공식 안내는 [Codex의 AGENTS.md](https://developers.openai.com/codex/guides/agents-md/)와 [Claude Code의 메모리·import](https://code.claude.com/docs/en/memory)를 참고합니다.

<a id="옛-claude-문서를-읽을-때"></a>

## 과거 CLAUDE 지침

[이관 전 CLAUDE 원문](HISTORY.md)은 삭제하지 않고 보존한 역사 자료입니다. 현재 실행 지시가 아닙니다.

외부 보관본의 이전 문서에서 말하는 `CLAUDE.md 4절`, `7절`, `12절`은 이 원문의 절 번호입니다. 새 루트 파일의 절 번호를 뜻하지 않습니다.

원문에는 이미 대체된 자동 커밋·푸시·정리 지시가 포함되어 있습니다. 그래서 루트 파일에서 이 원문을 import하지 않습니다.

<a id="작업-결과를-남길-때"></a>

## 작업 결과 기록

현재 변경·검증·실패·미확인은 [PROGRESS](progress/PROGRESS.md)를 갱신하고, 지속적으로 필요한 구조·설정·확장 계약은 해당 상시 문서에 반영합니다. 완료된 작업 로그와 일회성 커밋 가이드를 기본적으로 새 문서로 누적하지 않습니다. 상세 증거가 필요하면 Git 제외 로컬 결과를 보존하고 [HISTORY](HISTORY.md)에 복원 위치만 연결합니다. 새 계획 문서는 진행 중 작업에 필요할 때 만들고 완료 후 필요한 정보만 상시 문서로 통합합니다. 실제 작업 규칙을 새 로그에 다시 복제하지 않습니다.

새 문서의 위치와 기존 문서 구조는 [문서 안내](../README.md)를 따릅니다.
