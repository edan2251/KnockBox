# 현행 개발 명세

폼 전투 제거까지 반영한 main `2523cec`를 기준으로, Fusion 연결 이전과 2026-11-13 기본 예측 시험을 온라인 절에 구분해 설명합니다. 승인과 실제 구현·검증 상태는 [PROGRESS](progress/PROGRESS.md)에 둡니다. Main의 Brawl 흐름을 설명하며 게임 규칙을 새로 바꾸는 문서가 아닙니다.

**폼 전투는 없습니다.** 가위·바위·보 폼, 초기 폼 선택, 폼 전환, 에너지, 가드·패링, 바위 투사체, 보 휘두르기, 시험 공격 폼은 2026-11-11 삭제했습니다. 파이터는 늘 몸(Body) 폼이고 `RuleSet`은 잡기 스위치와 경기 흐름(`LegacyMatch`)만 가집니다. 기존 몸 폼 기록과 온라인 설정 대조를 위해 체크섬에 남긴 고정값 자리는 [미사용 기능 보존](INACTIVE_FEATURES.md#제거한-기능--폼-전투--2026-11-11)에 정리했습니다. `MatchRunner`는 Brawl 여부(`brawlExperiment`)와 관계없이 몸 폼 전투 값(`BrawlParams.Combat`)을 씁니다. Sandbox는 이동·경기 수치와 표시만 옛 기본값을 유지합니다.

## 작업 씬과 화면

Main은 메인·코드 참가·로비·VS·경기·카드·결과·재대결 흐름을 담당합니다. MapAuthoring은 맵 제작, Sandbox는 검증·재현용입니다. 캐릭터는 사각형 캐릭터 하나이며, 이전 외형 후보 씬(CharacterSample)은 2026-11-11에 삭제했습니다.

Main의 Match와 카메라·주요 UI·표시 담당은 씬에 배치되어 있습니다. Frontend___edit_these_screens는 실제 실행에 쓰는 프리팹 인스턴스입니다. Main의 UI와 화면 담당 참조가 빠지면 별도 화면을 만들지 않고 오류를 냅니다. 예외로 카메라 리그·팔레트·도형 라이브러리, FighterView 하위 부품, PostFx Volume은 비어 있으면 실행 중에 만듭니다. UI 필수 검사와 제작기 시험 연결은 씬 이름 `Main`으로 판별합니다. Sandbox·테스트의 절차식 초기화는 별도로 유지합니다.

화면 편집은 [팀 작업 안내](../team/TEAM_WORKFLOW.md)를 따릅니다. 실제 RectTransform·Text·Image와 프리팹 연결을 수정하고 저장·재열기·Play로 확인합니다. 저장 UI 초상은 경기 캐릭터 변경에 자동 동기화되지 않으므로 메인·VS·카드·결과를 따로 확인합니다.

## 코드 책임과 결정론

Game은 입력·틱 실행·튜닝·화면·온라인 세션을 연결합니다. Simulation은 Unity 엔진을 참조하지 않는 경기 판정과 상태·난수·체크섬을 담당합니다. Presentation은 상태를 읽어 외형·효과·소리를 표시합니다. 연출 전용 물리 결과를 경기 판정으로 되돌리지 않습니다.

SimWorld.Step의 고정 틱은 60Hz입니다. 같은 설정·맵·시드·양쪽 입력과 소비 순서를 유지해야 합니다. 상태 필드 추가 시 저장·복원·체크섬·StateDiff·입력 기록 영향을 함께 검토합니다. Unity 물리로 맵 판정을 임의 대체하지 않습니다.

주요 코드 위치는 Assets/_Project/Scripts 아래입니다.

- Game/Bootstrap/MatchRunner.cs: 틱 실행, 설정, 기록 재생
- Game/Bootstrap/MatchRunner.Maps.cs: 같은 MatchRunner의 맵 해석(제작기 시험 맵 → 등록 목록·selectedMap → 옛 txt/json)
- Game/Bootstrap/MatchPresenter.cs: 저장 참조와 표시 연결
- Game/UI/Frontend/: 화면 전환·입력·편집 구조
- Simulation/Systems/FighterCombat.cs: 전투·잡기·차징·무기 판정
- Game/Online/: 경기 세션·입력 전송, Photon Fusion 연결, 자동 검사용 메모리·모의 전송

## 현재 입력과 전투

MouseAimInputSource는 WASD 이동, Space 점프, 마우스 조준을 받습니다. 좌클릭은 짧게 떼면 펀치, 유지하면 차징입니다. 무기 사용은 현재 보류입니다. Shift의 공통 Dash·Charge 비트는 현재 Brawl 입력에서 제거합니다. 별도 Shift 차징 분기는 구 기록 호환용이며 현재 Main 조작이 아닙니다.

조준은 자기 슬롯의 파이터 위치에서 커서로 향하는 방향을 64방향 입력으로 변환합니다. 우클릭은 상대 잡기이며 잡은 상대는 좌클릭으로 던집니다. 무기 줍기·투척은 과거 기록용으로 보존합니다.

현재 돌진 최소 충전은 준비 8틱과 충전 12틱, 합계 20틱입니다. BrawlParams는 튜닝 위에 몸 크기 0.8배 등의 전용 규칙을 적용합니다. 차징의 이동 방향을 마우스 방향으로 새로 변경한 상태라고 가정하지 않습니다.

## 경기와 카드

CardCollectionRules가 현재 Main 경기 설정에 적용됩니다. 라운드 2승으로 세트 1점, 세트 5점으로 경기 승리입니다. 첫 VS 소개는 경기 시작에 한 번이며, 매 라운드는 재구성 후 3·2·1·GO로 시작합니다.

최종 승리 전 세트 패자가 한 방·맷집·멀리 던지기 중 하나를 선택해 획득 목록에 쌓습니다. CollectCardsOnly가 켜져 있으며 실제 능력 수정자는 적용하지 않습니다. 카드를 골랐다고 전투 능력이 증가하는 구현은 아직 아닙니다.

카드 클릭은 FrontendInputSource의 공통 선택 입력으로 전달되고, 확정된 입력을 MatchFlow가 보유 카드 상태에 적용합니다. UI의 즉시 피드백은 획득 확정과 구분합니다. Fusion 연결 이전은 이 규칙과 연출을 바꾸지 않습니다. 후속 능력·연출 작업의 경계와 세 장 전제는 [온라인·카드 확장 안내](ONLINE_MULTIPLAYER.md#카드-능력과-연출-확장)에 정리합니다.

FrontendController가 결과와 O/X 준비를 처리합니다. 로컬 연습과 양쪽 준비가 필요한 온라인 재대결을 구분합니다. O/P 즉사는 로컬 검수용이며 온라인·녹화·재생·동기화 검사에서는 차단합니다. 현재 실제 조작은 [플레이 검수](../team/PLAYTEST.md)에 있습니다.

## 무기·총알 보류

현재 새 경기에서는 무기 설정을 끕니다. 프라이팬·권총·탄약·투척 등 구현과 .meta·씬 참조는 [미사용 기능 보존](INACTIVE_FEATURES.md)에 모아 안내합니다. 과거 무기 기록은 원래 설정을 찾아 재생하며 이번 맵 확장에서 관련 신규 기능을 개발하지 않습니다.

## 맵 정의와 제작

MapDefinition 에셋이 지형·스폰·테마의 원본입니다. MapAuthoring은 이를 씬에서 배치·저장·재열기·등록·시험합니다. 씬 저장만으로 정의 에셋 저장을 대신하지 않습니다. 사각/볼록 고정 지형과 두 점 절단, 물리 상자, 독립 로프를 지원합니다. 맵 제작기 CP1~CP5 구현과 사용자 검수는 완료했으며 과거 계획은 [보관 안내](HISTORY.md)에서 찾습니다. 사용법은 [맵 제작 안내](../team/MAP_AUTHORING.md)를 따릅니다. 제작기의 맵 저장은 `Data/Maps/Validation/`의 기준 맵과 보호된 BrawlOriginal을 덮어쓰지 않으며, 작업은 사본에서 합니다.

정의의 같은 순서와 좌표가 ArenaDef 판정과 표시로 전달됩니다. 좌표는 float이며 수정하지 않은 좌표 비트를 보존합니다. 강제 반올림 없이 선택적 격자 스냅을 사용하고, 판정 순서는 명시적인 Order입니다. 제작기의 **도형 순서 정리**는 삭제 뒤 남은 도형을 기존 Order 순으로 연속 번호화하고, 중복 번호는 Hierarchy 순서로 정합니다. 위치·크기·질량·ID는 보존하며 정의 저장은 별도입니다. 이름만 정리할 때 기존 맵 체크섬은 바뀌지 않습니다. ID·Order 중복, 유효하지 않은 시작 위치와 미저장 편집을 검사합니다. 보호된 BrawlOriginal은 보존하고 별도 사본으로 작업합니다.

물리 상자는 별도 physicalBoxes 배열에 ID·순서·중심·크기·질량·플레이어 통과 여부를 저장합니다. MapPhysicalBoxHandle로 편집하고 LooseBox PropDef로 변환해 기존 PropPhysics/PropView에 전달합니다. 최대 48개이며 초기 회전은 0입니다. 새 상자는 라운드 시작부터 중력을 받습니다. 질량은 명시값을 쓰고 크기 편집으로 자동 변경하지 않습니다. 구 맵은 밀도×면적 및 잠든 시작을 그대로 사용합니다. 상자는 구분선 없이 기존 PropView의 상자별 밝기 차(±6%)로 표시합니다. 고정 조인트나 접착은 없습니다. 제작기의 기본 상자(1.5×1.5, 질량 2.25)와 긴 물리 기둥(1.5×4, 질량 4)은 같은 몸체의 배치 프리셋입니다. 기둥은 playerPassThrough=true로 저장합니다. 이 설정이 있으면 플레이어와의 몸·돌진·접촉 피해·서기/이동 전달을 제외하고, 지형·다른 물리 몸체와의 접촉·마찰·휴면은 그대로 유지합니다. 플레이어 발 스냅에서도 제외하지만 상자 윗면 스냅은 지원합니다. 기둥은 PropView.PassThroughColor의 `#222222`, 알파 130/255를 사용하며 테마나 상자 번호로 색이 바뀌지 않습니다. 조명에 의한 월드 밝기 연출은 적용됩니다. 기둥은 캐릭터보다 뒤의 Terrain 레이어에 표시합니다. 구 정의에서 새 필드가 없으면 false이므로 크기만 보고 기존 긴 상자를 일괄 변경하지 않습니다.

현재 Brawl 경기는 CombatTuning의 **점진적인 상자 밀림** 설정을 사용합니다. 원래 마찰 0.7과 바닥 마찰·질량·접촉 휴면 동기화는 유지합니다. 돌진 위력 24~36 구간에서 강제 밀어내기 보정을 점진적으로 적용하고, 상자 사이 마찰은 기본 최소 비율 0.15까지 낮아졌다가 최대 20틱 동안 부드럽게 회복합니다. 비율은 CombatTuning에서 조정할 수 있는 초기값입니다. 옆 접촉은 휴면 속도 기준 이상이면 느린 밀기도 전달하고, 상자 위에 가만히 서 있을 때의 휴면 보호는 유지합니다. 구 기록은 아래 호환 경로에서 조정 전 계산을 그대로 사용합니다.

새 로프는 MapDefinition.ropes의 `graph=true` 항목입니다. 끝 상자 ID·로컬 연결점, 선택적 시작 상자 ID·로컬 연결점 또는 월드 고정점, 줄 길이를 저장합니다. 고정점↔상자와 상자↔상자, 한 몸체의 여러 줄과 분기를 지원합니다. 물리 상자 최대 48개, 줄 최대 96개입니다. 로컬 연결점은 실제 길이 단위이며 Transform Scale을 다시 곱하지 않습니다.

MapDefinition.ToArena는 새 줄을 ArenaDef의 GraphRope 목록으로 변환합니다. PropPhysics의 기존 두 몸체 로프 속도/위치 풀이를 재사용하며 순서·반복 횟수는 고정합니다. 일반 줄은 하중이나 공격으로 끊어지지 않습니다. 줄은 최대 길이 제약이라 느슨해질 수 있습니다. 새 연결 몸체끼리도 실제 상자 충돌은 유지됩니다. 기존 마찰·질량·LooseTicks 등 전체 물리 기본값은 바꾸지 않았습니다.

독립 연결 상자는 MapPhysicalBox.connector와 connectorSpeedLoss로 정의합니다. 일반 LooseBox와 같은 사각 충돌·질량·회전이며, 편집기/게임은 ConnectorBoxVisual의 같은 아웃라인과 `#222222`, 알파 130/255 내부를 사용합니다. 밟기·점프·일반 충돌로는 부서지지 않습니다. ConnectorBodies가 펀치 활성 원과 차징/Thrown의 이동을 검사하고 PropInteraction보다 먼저 파괴하여 관통 시 벽꿍을 피합니다. 속도 감속 기본 15%는 상자별 조절값이며 파괴당 한 번만 적용합니다. 다른 고체에 가려진 공격과 먼저 가로막힌 이동은 제외합니다. 서로 다른 연결 상자를 통과하면 각각 감속합니다.

현재 Main은 CombatTuning의 **연결 상자 접촉 안정화**를 기본으로 사용합니다. 좁은 연결 상자를 밟을 때 실제 겹치는 접촉면 안의 점을 사용하고, 탑승 하중을 매 물리 소단계에서 줄 제약과 함께 풉니다. 이전처럼 줄 풀이가 끝난 뒤 큰 회전 하중을 한 번에 더하지 않습니다. 하중 임시 배열은 매 틱 상태에서 다시 계산하므로 저장/복원할 별도 상태를 추가하지 않습니다. 일반 상자·기둥의 질량·마찰·휴면값은 유지하며 실제 빠른 옆 충돌의 피해까지 없애지는 않습니다.

표시용 ConnectorContact/ConnectorBreak 사건은 몸체 번호·위치·방향·강도를 전달합니다. 일반 접촉은 작은 테두리 반응과 소리, 파괴는 짧은 섬광·테두리 8조각·연결된 줄의 0.16초 되감김과 기존 타격음·카메라/광원 반응을 사용합니다. 파괴된 몸체의 실제 판정은 즉시 제거하며 남은 표시만 짧게 재생합니다. 서 있는 동안 효과가 반복되지 않도록 표시 쪽 간격을 제한합니다. 파괴 순간에는 공격한 캐릭터의 몸이 짧게 눌렸다 복귀하고, 카메라는 공격 방향으로 한 번 밀린 뒤 0.18초 동안 3차 곡선으로 복귀합니다. 펀치에도 순간 확대를 적용합니다. 첫 표시 프레임을 보장한 약 0.05초 테두리 섬광 뒤 파편을 더 빠르게 퍼뜨립니다. MatchPresenter의 **연결 상자 타격 강조**로 화면 반동·확대·흔들림 강도를 조절하며 F7 흔들림 줄이기도 적용됩니다. 새 효과용 히트스톱이나 추가 피해 규칙은 없습니다. 고정 역할색은 PaletteAsset에 모읍니다. 로프는 `#555555`, 두께 0.12로 편집기/게임에 함께 적용하며 물리 제약과 무관합니다. 연결 상자 테두리·파괴 타격감은 기존 값을 유지합니다.

PropState.Graph는 새 연결 데이터가 있는 맵에만 활성화되는 값 타입 확장입니다. 파괴된 몸체를 두 uint 비트셋에 보존하고 몸체 번호를 지우거나 재정렬하지 않습니다. 줄의 해제는 양끝 몸체의 파괴 여부로 결정하므로 따로 누락될 가변 줄 목록이 없습니다. 파괴된 몸체의 접촉·발판·표시·그림자를 제외하고, 붙어 있거나 얹혀 있던 몸체를 깨웁니다. 남은 몸체의 선속도/각속도를 유지합니다. 새 상태는 체크섬·차이 검사·스냅샷에 포함되며 기존 맵에서는 확장 블록 자체를 방문하지 않아 과거 상태 해시가 같습니다.

제작기 복제·대칭은 선택된 양끝 몸체를 새 ID로 연결합니다. 한쪽이 선택되지 않은 줄은 복사하지 않습니다. 고정점 줄은 대상 상자와 함께 복사합니다. 상자 삭제는 양쪽에서 참조한 줄을 제거하며 Undo로 복원합니다. 저장·씬 재열기·미등록 Main 시험에 같은 정의를 사용합니다.

기존 `graph=false` 항목은 이전 PropDef.Rope/단일 PropJoint 경로를 그대로 사용합니다. RopeBreakMode 0=당김 파단, 1=일반 줄, 2=줄 위 비고체 연결부도 호환용으로 보존합니다. 과거 3종을 새로 고르는 제작 UI는 제거하고 해당 맵의 규칙을 읽기 전용으로 표시합니다. 데이터·판정·리플레이 경로는 삭제하지 않습니다. 기존 맵의 로프를 자동 전환하지 않으며 새 일반 연결 방식으로 바꾸는 버튼을 명시적으로 눌러야 합니다. 이 전환이 독립 연결 상자를 자동 생성하지는 않습니다. 과거 ROUNDS 내부 설정을 추정해 복사하지 않았으며 외부 코드·프리팹·모드 의존성은 추가하지 않았습니다.

볼록 지형은 MapBox.vertices의 반시계 방향 3~32개 꼭짓점이 원본입니다. 비어 있으면 기존 사각 경로입니다. 절단은 Solid만 지원하며 퇴화·오목·잘못된 범위를 거절합니다. MapTerrainCut은 경계 두 점으로 반평면을 잘라 기존 ID와 Order를 유지하고, 꼭짓점 시작 순서를 고정합니다. 임의 좌표를 격자에 강제 반올림하지 않습니다. 같은 꼭짓점을 ArenaDef, TerrainCollision, PropPolygonContacts, ArenaView, BackgroundView와 손발 표시 질의에 전달합니다. 판정에 Unity 물리는 쓰지 않으며 KO 파편의 PolygonCollider2D만 연출 전용입니다. 캐릭터는 축 정렬 몸체를 유지하고 약 45도까지 경사를 따라 걷습니다. 더 가파른 면은 미끄러지는 초기 기준이며 기존 사각 동작은 별도 경로로 보존합니다.

GameMaps의 MapCatalog가 경기 목록입니다. 1개면 반복, 2~8개면 고정 ID 정렬과 경기 시드의 결정론적 섞기 순환으로 직전 맵 ID 반복을 피합니다. 같은 지형이어도 ID가 다르면 별도 맵입니다. 제작기 시험은 미등록 상태에서도 선택한 저장 맵 하나와 테마를 Main 연습에 보냅니다. 시험은 로컬 전용이며 GameMaps나 Main의 저장 참조를 바꾸지 않습니다. Play를 끝내면 편집 씬과 이전 시작 씬 설정으로 돌아갑니다.

외곽 지형의 연출 분류는 상자 외곽이 경기장 경계에 닿는지 좌표와 크기로 판별합니다. 이름으로 인식하지 않으며 판정 자체를 애니메이션으로 이동하는 것은 아닙니다.

## 설정 적용

MovementTuning·CombatTuning → BrawlParams → CardCollectionRules가 현재 실행 설정에 관여합니다. 최종 값은 MatchRunner Inspector의 실제 적용 설정에서 확인합니다. 로컬 연습의 다음 라운드 갱신과 온라인·기록·재생 중 고정 설정을 구분합니다.

Main의 mapCatalog와 selectedMap은 맵 선택에 관여합니다. 등록 목록이 있으면 그 목록을 쓰고, 비었을 때 selectedMap 정의(없으면 Brawl)를 사용합니다. 새 경기는 같은 이름이면 정의를 옛 txt보다 먼저 쓰고, 과거 기록(ResolveRecordedArena)은 옛 txt/json을 먼저 씁니다. 과거 기록의 설정은 FindRecordedConfig로 찾습니다. 보존된 Brawl 체크섬 규칙은 MapDefinition.ToMatchArena 한 곳에 있습니다.

## 온라인과 리플레이

방 생성·코드 참가는 Fusion 2 Host/Client이며 에디터와 일반 빌드 모두 기본 예측·재시뮬레이션을 사용합니다. SDK 처리·송신·전투는 60Hz, SDK 최소 입력 지연은 **3틱**입니다. 입력 자동 추가 지연과 앱 지연 큐의 중복 적용은 끕니다. 2/4틱·64/128회 비교 경로는 정리했습니다. Host가 판정을 확정하고 Client가 전체 SimState를 복원·재실행하며 Host 자체는 롤백하지 않습니다.

LockstepSession은 프로토콜 9·설정·정렬된 맵 목록/전체 지형·시드 합의, 연결 상태·확정 체크섬·종료에 사용합니다. 실제 Photon 전투 입력은 Fusion 입력 버퍼를 사용합니다. ITransport·메모리/모의 전송과 비-Fusion 실행 분기는 오프라인 회귀 검사용으로 유지합니다. 과거 Relay·직접 UDP 접속은 제거했습니다.

기존 UI 배치·P1/P2 표시·최대 2인·Host 이탈 시 종료를 유지하며 이름 입력은 후속 기능입니다. 전투 그림은 예측 World, 카드·결과·일회성 사건과 입력 기록은 검증한 확정 World를 사용합니다. Simulation의 판정·60Hz·랜덤 소비와 입력 리플레이 v8/v9·과거 기대 체크섬은 바꾸지 않습니다.

HUD의 RTT는 Fusion SDK 관측값이며 제어 메시지 RTT는 예측 CSV에 따로 남깁니다. 어느 값도 순수 회선 Ping이나 버튼-화면 총 지연으로 단정하지 않습니다. SDK 상태·확정 입력 계약, 카드 확장, App ID 설정·검증 범위는 [온라인 개발 기준](ONLINE_MULTIPLAYER.md)을 봅니다. 현재 승인과 남은 검수는 [PROGRESS](progress/PROGRESS.md)에 있습니다.

새 연결망 또는 독립 연결 상자가 있는 맵은 **geometry schema 8**을 사용합니다. 기존 geometry 해시에 몸체 역할/감속, 순서 있는 로프 ID·양끝 몸체 번호·연결점·길이를 추가합니다. 기존 schema 2~7 값은 보존합니다. 입력 기록 v9와 온라인 프로토콜 9의 바이트 형식은 그대로이며 새 맵을 이해하지 못하는 실행 파일은 맵 해시 불일치로 거절합니다.

기존 맵은 입력 기록 v8과 기존 맵 해시를 유지합니다. 새 데이터의 형식은 다음과 같습니다.

- **입력 기록:** FormatVersion=8은 기존 경로이며 WrittenVersion이 해당 기록의 실제 버전입니다. 제작기 물리 상자나 다각형이 하나라도 있는 경기 목록은 v9로 기록하고 전체 지형·상자 위치/크기·ID/순서·질량·시작 휴면 방식을 검증합니다. v9 도입 전 실행 파일은 v9를 읽지 못합니다. 기록에 정의 전체가 내장되지는 않으므로 기록 당시 정의를 보존해야 합니다.
- **geometry schema:** 각 schema는 해당 데이터가 있는 맵에만 쓰이고, 없는 맵은 이전 schema 값(2/3)을 그대로 유지합니다. 플레이어 통과 몸체 4(모든 몸체의 통과 설정 포함), 기존 독립 로프 5, 볼록 지형 6, 이전 graph=false 경로의 일반 줄·줄 위 연결부 7(종류·연결부 위치·크기·감속 포함), 새 연결망·독립 연결 상자 8입니다. 모든 로프 설정·대상 몸체와 순서 있는 꼭짓점을 해시에 포함합니다.
- **온라인:** 프로토콜 9 그대로이며 같은 필드가 전체 맵 검증에 포함됩니다. 통과 설정이나 맵이 다른 피어는 거절합니다. 새 맵은 구 실행 파일과 맵 해시가 달라 연결·재생을 거절하고, 같은 기존 맵의 경로는 유지합니다. v9를 읽는 구 실행 파일도 새 통과 맵의 schema 4 해시가 달라 함께 경기할 수 없습니다.
- **구 기록의 한계:** v8 이하 기록은 통과 설정·새 로프·다각형을 검증할 수 없으므로 새 맵에 적용하지 않고 당시 맵을 요구합니다. 새 물리 맵의 v9 기록은 맵이 달라지면 재생을 거절합니다.
- **설정 체크섬:** 상자 반응 조정은 기록 형식을 바꾸지 않고 설정 체크섬으로 구분합니다. 조정 전 설정에는 새 필드를 해시하지 않으며, FindRecordedConfig가 현재 토글과 무관하게 구·신규 반응 후보를 찾습니다. 반응 설정이나 최소 마찰 비율이 다른 온라인 조합은 접속 단계에서 거절합니다.
- **무기:** 새 다각형과 활성 무기 설정의 조합은 명시적으로 거절하고 구 사각 맵의 무기 기록은 보존합니다.

이전 설정·입력 호환 경로를 남겨 두며, 새 결과로 과거 기대 해시를 덮어쓰지 않습니다. 다른 버전의 모든 기록이 재생된다는 보장은 없습니다. 순서·상태·난수·설정·맵이 바뀌면 호환 영향을 검토합니다.

접촉 안정화는 설정 체크섬으로 구분합니다. 꺼진 과거 설정은 새 필드를 해시하지 않으며 FindRecordedConfig가 안정화 이전/이후 후보를 모두 비교합니다. 기록 v8/v9·맵 schema·온라인 프로토콜 9의 바이트 형식과 과거 기대 체크섬은 변경하지 않습니다. 온라인 양쪽의 안정화 설정이 다르면 시작 전에 거절합니다. 이전 연결 상자 기록을 재생할 때는 당시 떨림/피해도 원래 결과대로 재현합니다.

연결 담당 파일과 경계는 [온라인 코드 지도](ONLINE_MULTIPLAYER.md#코드-지도), 도구 사용은 Tools/ReplayCheck/README.txt를 봅니다. Editor와 Player 사이의 과거 중간 틱 float 차이는 해결 완료로 표현하지 않습니다.

## 검증 상태와 한계

현재 변경의 컴파일·자동 검사·빌드·사용자 확인 결과는 [PROGRESS](progress/PROGRESS.md)에 기록합니다. 완료된 단계별 계획과 상세 실행 로그는 [보관 안내](HISTORY.md)에서 찾습니다. 서로 다른 버전·회차의 통과 수치를 합산하지 않습니다.

실제 온라인 손맛, 에디터 자체 오류, 새 clone의 실행·빌드, 다른 PC와의 Fusion 대전은 코드 이전만으로 완료로 간주하지 않습니다. 현재 우선 확인 항목은 [진행 현황](progress/PROGRESS.md)에 있습니다.
