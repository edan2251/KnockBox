# 현행 개발 명세

2026-11-07의 현재 소스를 확인한 개발 기준입니다. Main의 Brawl 흐름을 설명합니다. 게임 규칙을 새로 바꾸는 문서가 아니며, 과거 폼 전투와 호환용 코드 전체를 현재 조작으로 해석하지 않습니다.

## 작업 씬과 화면

Main은 메인·코드 참가·로비·VS·경기·카드·결과·재대결 흐름을 담당합니다. MapAuthoring은 맵 제작, Sandbox는 검증·재현용입니다. CharacterSample은 이전 외형 실험이며 현재 게임 캐릭터와 구분합니다.

Main의 Match와 카메라·주요 UI·표시 담당은 씬에 배치되어 있습니다. Frontend___edit_these_screens는 실제 실행에 쓰는 프리팹 인스턴스입니다. Main의 누락된 주요 참조를 별도 화면 생성으로 감추는 구조를 사용하지 않습니다. Sandbox·테스트의 절차식 초기화는 별도로 유지합니다.

화면 편집은 [팀 작업 안내](../team/TEAM_WORKFLOW.md)를 따릅니다. 실제 RectTransform·Text·Image와 프리팹 연결을 수정하고 저장·재열기·Play로 확인합니다. 저장 UI 초상은 경기 캐릭터 변경에 자동 동기화되지 않으므로 메인·VS·카드·결과를 따로 확인합니다.

## 코드 책임과 결정론

Game은 입력·틱 실행·튜닝·화면·온라인 세션을 연결합니다. Simulation은 Unity 엔진을 참조하지 않는 경기 판정과 상태·난수·체크섬을 담당합니다. Presentation은 상태를 읽어 외형·효과·소리를 표시합니다. 연출 전용 물리 결과를 경기 판정으로 되돌리지 않습니다.

SimWorld.Step의 고정 틱은 60Hz입니다. 같은 설정·맵·시드·양쪽 입력과 소비 순서를 유지해야 합니다. 상태 필드 추가 시 저장·복원·체크섬·StateDiff·입력 기록 영향을 함께 검토합니다. Unity 물리로 맵 판정을 임의 대체하지 않습니다.

주요 코드 위치는 Assets/_Project/Scripts 아래입니다.

- Game/Bootstrap/MatchRunner.cs: 틱 실행, 설정, 맵, 기록 재생
- Game/Bootstrap/MatchPresenter.cs: 저장 참조와 표시 연결
- Game/UI/Frontend/: 화면 전환·입력·편집 구조
- Simulation/Systems/FighterCombat.cs: 전투·잡기·차징·무기 판정
- Game/Online/: Relay·세션·입력 전송

## 현재 입력과 전투

MouseAimInputSource는 WASD 이동, Space 점프, 마우스 조준을 받습니다. 좌클릭은 짧게 떼면 펀치 또는 보유 무기 사용, 유지하면 차징입니다. Shift의 공통 Dash·Charge 비트는 현재 Brawl 입력에서 제거합니다. 별도 Shift 차징 분기는 구 기록 호환용이며 현재 Main 조작이 아닙니다.

조준은 자기 슬롯의 파이터 위치에서 커서로 향하는 방향을 64방향 입력으로 변환합니다. 우클릭은 상대 잡기 또는 무기 줍기이며 보유 무기는 우클릭으로 던집니다. 잡은 상대는 좌클릭으로 던집니다.

현재 돌진 최소 충전은 준비 8틱과 충전 12틱, 합계 20틱입니다. BrawlParams는 튜닝 위에 몸 크기 0.8배 등의 전용 규칙을 적용합니다. 차징의 이동 방향을 마우스 방향으로 새로 변경한 상태라고 가정하지 않습니다.

## 경기와 카드

CardCollectionRules가 현재 Main 경기 설정에 적용됩니다. 라운드 2승으로 세트 1점, 세트 5점으로 경기 승리입니다. 첫 VS 소개는 경기 시작에 한 번이며, 매 라운드는 재구성 후 3·2·1·GO로 시작합니다.

최종 승리 전 세트 패자가 한 방·맷집·멀리 던지기 중 하나를 선택해 획득 목록에 쌓습니다. CollectCardsOnly가 켜져 있으며 실제 능력 수정자는 적용하지 않습니다. 카드를 골랐다고 전투 능력이 증가하는 구현은 아직 아닙니다.

FrontendController가 결과와 O/X 준비를 처리합니다. 로컬 연습과 양쪽 준비가 필요한 온라인 재대결을 구분합니다. O/P 즉사는 로컬 검수용이며 온라인·녹화·재생·동기화 검사에서는 차단합니다. 현재 실제 조작은 [플레이 검수](../team/PLAYTEST.md)에 있습니다.

## 무기

프라이팬은 근접, 권총은 원거리 무기입니다. 스폰·소유·공격·탄약·투척 등 판정 상태는 Simulation이 관리하고 WeaponVisual과 BrawlWeaponView가 표시합니다. 라운드 내 한 번 생성하고 라운드가 끝나면 정리합니다. 보유 중 우클릭 투척과 벽꿍 시 놓치기, 바닥 무기 재획득 경로가 있습니다.

임시 수치는 BrawlWeaponParams와 BrawlParams에서 확인합니다. 외형 변경과 판정 변경은 별개입니다. 총알·무기·효과 풀 등 동적 생성은 필요한 예외이며 이번 문서 정리에서 생성 방식이나 수치를 변경하지 않았습니다.

## 맵 정의와 제작

MapDefinition 에셋이 지형·스폰·테마의 원본입니다. MapAuthoring은 이를 씬에서 배치·저장·재열기·등록·시험합니다. 씬 저장만으로 정의 에셋 저장을 대신하지 않습니다. 사각 지형이 지원 대상이며 원·경사 다각형의 판정 구현은 보류입니다.

정의의 같은 순서와 좌표가 ArenaDef 판정과 표시로 전달됩니다. 좌표는 0.001 정밀도, 판정 순서는 명시적인 Order입니다. ID·Order 중복, 유효하지 않은 시작 위치와 미저장 편집을 검사합니다. 보호된 BrawlOriginal은 보존하고 별도 사본으로 작업합니다.

GameMaps의 MapCatalog가 경기 목록입니다. 1개면 반복, 2~8개면 고정 ID 정렬과 경기 시드의 결정론적 섞기 순환으로 직전 맵 ID 반복을 피합니다. 같은 지형이어도 ID가 다르면 별도 맵입니다. 제작기 시험은 선택한 저장 맵 하나를 Main에 보냅니다.

외곽 지형의 연출 분류는 상자 외곽이 경기장 경계에 닿는지 좌표와 크기로 판별합니다. 이름으로 인식하지 않으며 판정 자체를 애니메이션으로 이동하는 것은 아닙니다.

## 설정 적용

MovementTuning·CombatTuning → BrawlParams → CardCollectionRules가 현재 실행 설정에 관여합니다. 최종 값은 MatchRunner Inspector의 실제 적용 설정에서 확인합니다. 로컬 연습의 다음 라운드 갱신과 온라인·기록·재생 중 고정 설정을 구분합니다.

Main의 mapCatalog와 selectedMap은 맵 선택에 관여합니다. 등록 목록이 있으면 그 목록을 쓰고, 비었을 때 선택 맵/Brawl 경로를 사용합니다. 과거 기록은 FindRecordedConfig·ResolveRecordedArena 등의 호환 경로를 거칩니다.

## 온라인과 리플레이

현재 온라인은 Unity Relay 전송과 LockstepSession입니다. 온라인 롤백 구현이 완료된 상태가 아닙니다. 프로토콜은 9이며 OnlineMapManifest로 정렬된 맵 목록·전체 지형과 시작 설정을 비교합니다.

InputRecording.FormatVersion은 8입니다. 이전 설정·입력 호환 경로를 남겨 두며, 새 결과로 과거 기대 해시를 덮어쓰지 않습니다. 다른 버전의 모든 기록이 재생된다는 보장은 없습니다. 순서·상태·난수·설정·맵이 바뀌면 호환 영향을 검토합니다.

연결 담당 파일과 경계는 [온라인 코드 지도](ONLINE_CODE_MAP.md), 도구 사용은 Tools/ReplayCheck/README.txt를 봅니다. Editor와 Player 사이의 과거 중간 틱 float 차이는 해결 완료로 표현하지 않습니다.

## 검증 상태와 한계

이번에는 소스·씬·설정·참조를 읽고 문서를 정리했습니다. Unity 컴파일·Play·빌드·2PC Relay를 새로 실행하지 않았습니다. 과거 이관의 242 EditMode·7 PlayMode·Windows 빌드·기준 리플레이 2개 결과는 외부 보관 기록에 있으며 이번 검증 결과와 다릅니다.

실제 온라인 손맛, 에디터 자체 오류, 새 clone의 실행·빌드, 다른 PC와의 새 Relay 대전은 완료로 간주하지 않습니다. 현재 우선 확인 항목은 [진행 현황](progress/PROGRESS.md)에 있습니다.
